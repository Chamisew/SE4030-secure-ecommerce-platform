--------------------------------------------------------------------------------
Command:

Response Received:
HTTP/1.1 401 Unauthorized

{
  "message": "Full authentication is required to access this resource",
  "timestamp": "2026-09-25T13:45:46.395406200Z",
  "error": "Unauthorized",
  "path": "/test-email",
  "status": 401
}

Observation:
By removing `.securityMatcher("/api/**")` from SecurityConfig, Spring Security
applies globally across all routes. Unauthenticated requests to /test-email
are immediately intercepted with HTTP 401 Unauthorized and receive standard
security headers (X-Frame-Options, X-Content-Type-Options, Cache-Control).

--------------------------------------------------------------------------------
2. Exploit Attempt: Authenticated Non-Admin User (ROLE_USER)
--------------------------------------------------------------------------------
Request:
GET /test-email
Authorization: Bearer <valid_ROLE_USER_token>

Response Received:
HTTP Status: 403 Forbidden
Response Body:
{"message": "Access Denied", "error": "Forbidden", "status": 403}

Observation:
The endpoint requires ROLE_ADMIN. Non-admin users cannot trigger arbitrary
outbound emails.

--------------------------------------------------------------------------------
3. SMTP Log Verification
--------------------------------------------------------------------------------
No emails were received by the local SMTP sink during the unauthorized test calls.
Email dispatch is completely prevented.

Comparison with BEFORE:
BEFORE Fix: Returned HTTP 200 OK with body "Email sent!" and dispatched email.
AFTER Fix:  Anonymous -> HTTP 401 Unauthorized.
            ROLE_USER -> HTTP 403 Forbidden.
